# Architecture & product decisions (v2.0)

Each decision records what was chosen and why. "Baseline" = the v0.6 project in `opendmo-betterV-v1.0.zip`.

| # | Decision | Rationale |
|---|---|---|
| D-001 | Build v2 in `opendmo/`; the baseline is unzipped to `baseline/` (git-ignored) and never modified; the ZIP stays in the repo root. | Keeps the reference immutable and the repository free of duplicated sources. |
| D-002 | Single process: FastAPI serves `/api` **and** the Next.js static export (`output: 'export'`, `trailingSlash: true`) from `backend/app/static`. | End users need only Python; one port, one origin, simple CSP. |
| D-003 | No frontend demo fixtures and no frontend fallback mode (baseline had both). All data, including DEMO, comes from the backend. | "Backend owns all logic"; one source of truth; DEMO rows are flagged in the database and removable. |
| D-004 | CONTRACT.md §5 palette and typography are superseded by the Petra system (black `#0E0E10`, panels `#16161A/#1D1D22`, cream `#F4ECDD/#BDB4A3`, red `#B3202A/#D8343F`, status ok/watch/risk) and JetBrains Mono everywhere, bundled via `@fontsource/jetbrains-mono`. The IA chain, four fixed cores and data-integrity rules are kept. See `CONTRACT.md` v2. | Explicit instruction in the v2 brief; readability on black and print-friendly light theme. |
| D-005 | Plain CSS with design tokens instead of Tailwind. | Fewer dependencies, the theme toggle is a single attribute swap, components cannot leak default palettes. |
| D-006 | One unified, append-only `runs` table for calculations, forecasts and models (baseline had separate tables). Each run stores inputs, parameters (incl. per-input data sources), dataset id + version + content hash, a snapshot of the method definition, outputs, data quality, software version, timestamp. | Uniform provenance, re-run, bundles, briefs and history. The method snapshot keeps old runs interpretable after a method version bump. |
| D-007 | Methods are Python dataclasses (`Method`) with params, outputs, formula, method text, references (citation + BibTeX), weights, limitations, a *screening* flag and **known-value cases** that double as unit tests. `docs/CALCULATIONS.md` is generated from the registry and a test fails if it is stale. | Documentation cannot drift from code. |
| D-008 | Forecasting in pure numpy: seasonal-naïve, OLS linear trend, additive Holt-Winters with centred/detrended initialisation and coarse grid search; hold-out back-test with MAE, RMSE, MAPE and MASE. | No statsmodels/scipy dependency (smaller install, easier Windows/macOS); exactness verified on synthetic series. |
| D-009 | CSV import is a staged, token-based pipeline (upload → detect → map → dry-run → commit). Idempotency: unique (dataset, period, variable) plus a unique (dataset, file SHA-256) import record; the original file is archived under `data/uploads/`. | Re-importing never duplicates; every value is traceable to a file hash. |
| D-010 | Encoding detection without extra packages: BOM → UTF-8 → Windows-1252 → Latin-1. | Covers Excel exports on Windows and macOS without `chardet`. |
| D-011 | Range violations (variable min/max) are **errors**; robust outliers (modified z-score > 3.5, Iglewicz & Hoaglin) are **warnings** and stored with flag `outlier`. | Impossible values must not enter; unusual-but-possible values should be visible, not silently dropped. |
| D-012 | Quality score 0–100 = completeness over the regular period grid × (1 − 0.5·outlier share − 0.25·estimated share) − 10 per missing required variable − 20 × range-violation share; high ≥ 80, moderate ≥ 60. | Keeps the baseline's 0–100 score but accounts for gaps in the time series. |
| D-013 | Backups are engine-agnostic: every table as JSON + model store + archived uploads in one zip; restore replaces all rows in one transaction after writing a safety backup. | Works identically on SQLite and PostgreSQL; human-inspectable. |
| D-014 | Dataset preference: when user data and DEMO data exist for the same kind, KPIs, charts and "fill from data" use the newest non-archived **user** dataset. | Real data must win over synthetic data automatically. |
| D-015 | Removing a DEMO pack also deletes runs flagged DEMO for that destination (and their scenarios). | "Remove demo data" should leave no synthetic-derived results behind; runs computed from user data are untouched. |
| D-016 | Timestamps are stored as UTC with an explicit offset on every engine (`UTCDateTime` type). | SQLite drops tzinfo; provenance timestamps must be unambiguous. |
| D-017 | Swagger UI (`/docs`) disabled; `/api/openapi.json` kept and `docs/API.md` generated from the routes. | Swagger loads JS/CSS from a CDN — forbidden by the offline rule. |
| D-018 | Content-Security-Policy `default-src 'self'` (inline scripts/styles allowed for the Next.js export). The browser gate (`scripts/ui_check.mjs`) fails on any non-local request. | Enforces "no remote network calls at runtime". |
| D-019 | The launcher (`run.py`, stdlib only) creates `.venv`, installs pinned requirements once (hash-stamped), supports an offline `wheels/` folder, picks the next free port, opens the browser after `/api/health` succeeds, and bypasses HTTP proxies for localhost. On POSIX it `exec`s the venv interpreter so signals reach the server. | Found during testing: proxied environments made the localhost health check hang. |
| D-020 | Port and data directory are launcher settings stored in `opendmo.settings.json` next to `run.py` (restart required); all other settings live in the database. | They must be known before the database is opened. |
| D-021 | GIS layers are stored as validated GeoJSON (WGS84 range check, ≤ 8 MB) in a JSON column; `database/schema.sql` adds a PostGIS view `gis_features` for QGIS users. The map is a schematic equirectangular SVG with a hand-simplified basemap. | Portable across engines, no tiles, honest labelling. |
| D-022 | Destination attributes carry editable method defaults (e.g. Cifuentes area, hours, MC; gauge danger level, elevation). They are suggestions shown as inputs, never hidden constants. | Destination-specific assumptions stay visible and editable. |
| D-023 | Composite indices (pressure, site condition, sentiment status, hazard screens, ecosystem stress, readiness, STII, sustainability screen) are flagged `screening=True`, must declare limitations (enforced by a test), and are labelled "Screening indicator — not a certification" everywhere. | Honesty requirement. |
| D-024 | The release ZIP is deterministic (sorted entries, fixed timestamps), sets executable bits for `run.py`, `start-mac.command`, `start-linux.sh`, normalises their line endings, and ships with a `.sha256`. It is committed at `opendmo/release/opendmo-v2.0.zip`. | Reproducible artifact; verifiable download. |
| D-025 | PostgreSQL is supported through SQLAlchemy and the whole pytest suite runs against PostgreSQL in CI (`OPENDMO_TEST_DATABASE_URL`). psycopg is an optional requirement file. | Keeps the zero-config default light while proving the optional engine works. |
| D-026 | Next.js 15.5 (not 16) with ESLint 8 `next lint`. | Stable static-export behaviour and lint integration; pinned exactly. |
